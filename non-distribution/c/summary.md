# CS1380 M0 - System Overview 

This project implements a centralized, Unix-style search engine as a streaming pipeline.  
`engine.sh` drives the system by repeatedly reading URLs from `d/urls.txt` and processing each one. For every URL, `crawl.sh` uses `curl` to download the page and splits the HTML stream: `getURLs.js` parses the HTML DOM, extracts all `<a href>` links, resolves them to absolute URLs using the current page as the base, and prints them so new (unvisited) URLs can be appended back into `d/urls.txt`, while `getText.js` strips HTML tags and outputs plain text. That text flows into `index.sh`, which runs a sequence of transforms: `process.sh` normalizes text into one lowercase ASCII word per line and removes stopwords, `stem.js` reduces each word to its root form, `combine.sh` generates unigrams/bigrams/trigrams, and `invert.sh` counts how many times each term appears in the current page and emits a local inverted index of the form `<term> | <frequency> | <url>`. This local index is piped into `merge.js d/global-index.txt`, which reads the existing global index from disk, merges in the new counts by term and URL (summing frequencies when needed), sorts URLs by descending frequency and terms alphabetically, and prints the updated global index, which `index.sh` writes back to `d/global-index.txt`. At any time, `query.js` can read `d/global-index.txt` and return the most relevant URLs for 1–3 query terms based on stored frequencies. All components communicate only via stdin/stdout and files, making the system modular, testable, and suitable for later distribution.
