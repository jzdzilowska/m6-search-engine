04 - Design Choices
Key Technical Decisions
Coordinator-Driven Storage
Workers only fetch pages and return content via RPC. The coordinator performs all distribution[gid].store.put() calls, because workers lack the group proxy initialization needed for distributed writes.
SHA-256 Prefix Deduplication
Instead of storing full URLs (avg ~80 chars each), we store 16-char SHA-256 prefixes in visited/queued sets. Cuts memory ~5x while keeping collision probability negligible at 100K scale.
Streaming MR Results
Index results never accumulate in coordinator memory. Each MapReduce chunk streams directly to the distributed store via read-merge-write for overlapping terms.
Crash-Resumable Crawl State
Every 500 pages: visited hashes, frontier, and URL chunks serialize to the distributed store. On restart with --resume, crawling picks up exactly where it left off.
Round-Robin Wave Dispatch
Each wave dequeues 30 URLs, distributes round-robin across workers (10 per worker with 3 nodes). Simple modular arithmetic achieves even load distribution with zero coordination overhead.
05 - Crawling & Retrieval
Wave-Based BFS + TF-IDF
Coordinator manages a 200K-entry frontier. Each wave dispatches 30 URLs round-robin to 3 workers via crawl-fetch RPC. Workers fetch, extract text via html-to-text, parse outlinks via regex, and return results.

Pipeline: Tokenize → Porter stem → dedup terms → parallel postings fetch → TF-IDF score → PageRank boost → rank top 20.
Snippets: For each result, fetch stored page content and select the sentence with highest query-term overlap.
