01 - System Overview
End-to-End Architecture
Four EC2 instances run a coordinator/worker topology. The coordinator manages the crawl frontier, dispatches work via RPC, orchestrates MapReduce jobs, and serves the search UI. Workers fetch pages, execute map/reduce phases, and store sharded data locally.

02 - Distributed Crawling
Wave-Based BFS
Coordinator manages a 200K-entry frontier. Each wave dispatches 30 URLs round-robin to 3 workers via crawl-fetch RPC. Workers fetch, extract text + outlinks, and return results. Coordinator stores pages and deduplicates outlinks.

Persistence: State checkpointed every 500 pages. Crawl survives crashes. URL list stored in chunks for streaming recovery.
Deduplication: 16-char SHA-256 prefix hash per URL. Visited and queued sets prevent redundant fetches.
Workers: 15s timeout, 5MB body cap, one redirect, html-to-text + jsdom for link parsing.

NLP Pipeline: Strip non-alpha → lowercase → stopword filter (~130 words) → Porter stemmer (70+ lines inlined in mapper) → TF counting.

04 - Challenges
Design Decisions
No RPC Timeout
A silent worker hangs the entire wave forever. Mitigated by tmux sessions and crash-resumable state.
Function Serialization
MapReduce ships mapper/reducer as strings to workers. No closures, no imports. All logic (stemmer, stopwords) must be inlined.
Coordinator as Single Point
All page storage flows through coordinator for consistency. Workers only fetch and return results.
Memory at Scale
Visited set grows to 60K+ hashes in memory. Required --max-old-space-size=6144 on all nodes.
05 - Extra Credit Extensions
PageRank + Spell Check + Debug EC
① PageRank (Iterative Link Analysis)
PR(p) = (1-d)/N + d · Σ PR(q)/L(q) d = 0.85 · N = total pages · L(q) = outlinks of q · 10 iterations · dangling mass spread uniformly
Query boost: score *= 1 + max(0, log(PR·N)). Well-linked catalog/index pages rank higher.
② Spell Check / Query Suggestions
When a query term has no index hits, generate all 1-edit variants (insert, delete, replace, transpose). Check the top 30 candidates against the index store. If a variant has df >= 2, suggest it as "Did you mean: X?"
③ Highlighted Snippets
Matched query tokens are wrapped in <mark> tags in result snippets, giving visual feedback on why a result matched.
④ Debug / Status Endpoint
GET /status returns JSON: uptime, total queries served, indexed docs, worker count, heap memory usage, and node version.
06 - Query & Retrieval
TF-IDF + PageRank Scoring
score(url) = Σ tf(t,url) · log(1 + N/(1+df)) · (1 + max(0, log(PR·N))) Per-term TF-IDF with logarithmic PageRank boost
Pipeline: Tokenize query → Porter stem → deduplicate → fetch postings from distributed index store → score all candidate URLs → rank top 20.
Snippets: For each result, fetch the stored page text and select the sentence with the highest overlap with raw query tokens.
Web UI: Minimal black/white design with Inter font. Search form at GET /, results at GET /search?q=. Each result shows title, URL, snippet, score, and per-term tags.
